YOLOv8 Crack Detection System | Residential & Commercial Inspection

Detect.
Classify.
Report.

A computer vision pipeline that ingests inspection footage, detects structural cracks frame-by-frame using a fine-tuned YOLOv8 model, applies temporal filtering to reduce false positives, and outputs annotated video with severity-classified detection reports.

1 object class
3 severity levels

{ PIPELINE }
Three Scripts.
01
prepare_dataset.py
Organizes raw images and YOLO-format label files into the required train/val split directory structure. Finds all supported image formats, shuffles with a fixed seed for reproducibility, copies images and corresponding label files into split directories, and generates the data.yaml config file YOLO needs. Accepts a configurable validation fraction (default 0.2) and class names list.
python prepare_dataset.py \
--images_dir /path/to/raw_images \
--labels_dir /path/to/raw_labels \
--output_dir ./dataset \
--val_split 0.2 \
--class_names crack
02
train.py
Loads the specified pretrained YOLOv8 checkpoint and fine-tunes it on your crack dataset using transfer learning from COCO weights. Calls model.train() via the Ultralytics API with configurable epochs, batch size, image size, learning rate, and IoU threshold. Saves the best and last checkpoints. After training, automatically runs validation and reports mAP50 and mAP50-95 metrics.
python train.py \
--data ./dataset/data.yaml \
--epochs 100 \
--model yolov8n.pt
03
detect_video.py
Loads the trained model weights and processes each input video frame-by-frame using streaming prediction. For every detection it extracts the bounding box, confidence, class, calculates a severity score from the combined size/confidence heuristic, and applies temporal filtering across consecutive frames. Outputs an annotated video with drawn bounding boxes, a JSON report, and a CSV report per input video. Supports batch processing of entire folders.
python detect_video.py \
--model runs/detect/crack_yolo/weights/best.pt \
--source inspection.mp4 \
--output ./results

{ TRANSFER LEARNING }
Pretrained COCO Weights
All model variants start from weights pretrained on the COCO dataset, providing rich feature extraction from 80 object categories. Fine-tuning on crack images leverages these learned low-level features , edges, textures, shapes , meaning far fewer crack images are needed compared to training from scratch. Typically converges in 50–100 epochs.
{ DATA FORMAT }
YOLO Annotation Format
Each image requires a paired plain-text label file. Each line encodes one object: class_id x_center y_center width height, all normalized 0–1 relative to the image dimensions. For crack detection, class_id is always 0. LabelImg, CVAT, and Roboflow all export this format directly.
{ METRICS }
mAP50 and mAP50-95
After training, the best model is automatically validated. mAP50 (mean Average Precision at 0.5 IoU threshold) is the primary metric for crack detection. mAP50-95 averages across IoU thresholds from 0.5 to 0.95, giving a stricter measure of localization accuracy. Monitor both via TensorBoard during training.
{ HOW YOLO WORKS }
How YOLO Works

YOLO (You Only Look Once) reframes object detection as a single regression problem, directly predicting bounding boxes and class probabilities from full images in one evaluation.

01
Input & Backbone
An input image is passed through a convolutional neural network (e.g., Darknet 53, CSPNet, or EfficientNet) to extract a rich feature map.
02
Grid Creation
The feature map is split into an S × S grid (typical S = 13, 26, or 52). Each grid cell is responsible for detecting objects whose center falls within it.
03
Bounding Box Predictions
Each cell predicts B bounding boxes (usually B=2 or 3). For each box it predicts:
  • x, y: center coordinates relative to the cell bounds
  • w, h: width and height relative to the whole image
  • objectness score: probability that the box contains an object
  • class probabilities: one per class (softmax over classes)
04
Confidence Score
The final confidence for a box = objectness × class probability. This reflects both how likely the box contains an object and how accurate the predicted class is.
05
Non Maximum Suppression (NMS)
All predictions are filtered by a confidence threshold, then overlapping boxes of the same class are suppressed, keeping the highest scoring one.
06
Single Pass Inference
Because predictions come from one forward pass, YOLO runs at real time speeds (45 to 150 FPS on a GPU) while still leveraging the expressive power of deep CNNs.

{ SEVERITY }
Classification

The severity label is a heuristic visual prominence indicator for triaging inspection footage , not a calibrated crack-width measurement. It combines a size-based score (60% weight) from the normalized bounding box diagonal and the model's detection confidence (40% weight).

{ SEVERITY LEVEL 01 }
Minor
Score < 0.3
Small or low-confidence detection. Hairline surface cracks, early-stage seam separation, or stress marks. Flag for monitoring but unlikely immediate structural concern.
{ SEVERITY LEVEL 02 }
Moderate
0.3 , 0.6
Visible crack with branching or medium-width. Warrants professional inspection. Could indicate settling, moisture infiltration, or early structural movement in the substrate.
{ SEVERITY LEVEL 03 }
Severe
Score > 0.6
Large bounding box with high confidence. Structural or settlement crack with significant width or branching. Immediate professional assessment recommended. Do not use as sole basis for structural decisions.
Temporal Filtering
To reduce false positives in video, the detector tracks detections across consecutive frames. A detection is only counted in the final output if it appears in a minimum number of recent frames , the temporal_min_hits threshold. Spatial proximity matching (distance_threshold) links detections across frames to the same physical crack. Flicker detections from noise, compression artifacts, or brief occlusions are suppressed.
Severity Formula
60% Size score , normalized diagonal of bounding box relative to full frame diagonal
40% Confidence score , model's raw detection confidence for that bounding box
< 0.3 Minor , small or low-confidence, monitor
0.3–0.6 Moderate , professional inspection recommended
> 0.6 Severe , immediate assessment required
{ ARCHITECTURE }
Code Structure
{ SCRIPT 01 }
prepare_dataset.py
Four core functions: find_images() locates all supported formats, split_train_val() shuffles and divides with a fixed seed, copy_split() copies image/label pairs to output directories, and write_data_yaml() creates the YOLO config. If no labels directory is provided, only images are organized.
{ SCRIPT 02 }
train.py
Parses CLI arguments, instantiates the YOLOv8 model via the Ultralytics YOLO class, calls model.train() with the specified parameters, then calls model.val() on the best checkpoint. Training runs save to runs/detect/crack_yolo/. Checkpoints: weights/best.pt and weights/last.pt.
{ SCRIPT 03 }
detect_video.py
Streams frames via OpenCV VideoCapture, runs YOLO prediction in streaming mode, applies the size-confidence severity heuristic per detection, applies temporal filtering across frame history, writes annotated frames back via VideoWriter, and exports JSON and CSV reports with per-detection metadata.
{ FORMAT }
Dataset Output
The prepare_dataset.py script creates: dataset/images/train/, dataset/images/val/, dataset/labels/train/, dataset/labels/val/, and dataset/data.yaml pointing to these paths with the class names list.
{ OUTPUT }
Detection Reports
Each video produces three files: {name}_annotated.mp4 with bounding boxes drawn on every frame, {name}_report.json with all detections indexed, and {name}_report.csv for analysis in spreadsheet tools. Each record includes frame number, timestamp, confidence, bbox coords, dimensions, and severity.
{ MONITORING }
TensorBoard
Ultralytics logs training metrics to runs/detect/crack_yolo/ in TensorBoard format. Launch with tensorboard --logdir runs/detect to visualize loss curves, mAP progression, precision, recall, and confusion matrix throughout training in real time.
{ CAPABILITIES }
Features
01
GPU and CPU Support
Runtime
All three scripts work on CPU-only machines, with GPU (NVIDIA CUDA) recommended for training and faster inference. Specify --device 0 for the first NVIDIA GPU, or --device cpu to force CPU. YOLOv8n is the recommended starting point for CPU-only environments.
02
Batch Video Processing
Detection
Pass a folder path to --source and the detector processes every video file in that directory, generating annotated video, JSON, and CSV outputs for each one. Use --no_save_video to skip annotated video generation and run significantly faster when you only need the detection reports.
03
Configurable Thresholds
Detection
Detection confidence threshold (--conf, default 0.25), IoU threshold for NMS (--iou), temporal minimum hits, and spatial distance threshold are all configurable at runtime. Tune these based on your precision/recall requirements and video characteristics.
04
Labeled Bounding Boxes
Output
The annotated video draws bounding boxes around every detected crack with the confidence score and severity level labeled in each box. Uses OpenCV drawing primitives. Color-coding by severity is supported via configuration. The annotation is written to a new video file, preserving the original source file.
05
Reproducible Dataset Splits
Training
The train/val split uses a fixed random seed ensuring the same images always end up in the same split. This means training runs are reproducible, validation results are comparable across model sizes, and you can safely re-run prepare_dataset.py without reshuffling previously split data.
06
Early Stopping
Training
Use the patience parameter to stop training automatically when the validation metric stops improving for a specified number of epochs. Prevents overfitting without manual monitoring. Combined with TensorBoard visualization, this keeps training efficient and prevents wasted compute on models that have already converged.
{ QUICKSTART }
Get Running
01
Install Requirements
Install the four required packages. Ultralytics bundles PyTorch as a dependency , it will install the CPU or CUDA version appropriate for your system. OpenCV handles video capture and frame writing. NumPy handles array operations throughout.
pip install -r requirements.txt

# requirements.txt contains:
# ultralytics opencv-python PyYAML tqdm numpy
02
Prepare Your Dataset
Annotate crack images using LabelImg, CVAT, or Roboflow , all export YOLO format directly. Aim for at least a few hundred labeled examples covering different crack types (hairline, structural, stair-step, settlement), surfaces (drywall, concrete, brick, stucco), and lighting conditions. Include images without cracks to reduce false positives.
python prepare_dataset.py \
--images_dir ./raw_images \
--labels_dir ./raw_labels \
--output_dir ./dataset \
--val_split 0.2
03
Train the Model
Start with yolov8n.pt and 50 epochs to verify your pipeline before committing to a full run. Monitor via TensorBoard. If training diverges, try lowering --lr0. If GPU memory runs out, reduce --batch. Upgrade to yolov8s.pt or larger when you have adequate GPU resources.
python train.py \
--data ./dataset/data.yaml \
--epochs 100 \
--model yolov8s.pt \
--batch 16 \
--imgsz 640
04
Run Detection
Point the detector at your trained weights and inspection video. Start with the default confidence threshold of 0.25 , lower it if you're missing cracks, raise it to reduce false positives. The detector prints a per-video summary of total detections and severity breakdown to console.
python detect_video.py \
--model runs/detect/crack_yolo/weights/best.pt \
--source ./inspection_videos \
--output ./results \
--conf 0.25
{ LIMITATIONS }
Disclaimer

This tool is designed for automated screening and triage of inspection footage. It is not a replacement for professional structural engineering assessment. The following limitations apply.

01
Not a Measurement Tool
Severity classification is heuristic and based on visual prominence in the frame. It does not measure physical crack width, depth, or rate of growth. Do not use severity scores to make structural load decisions without professional on-site measurement.
02
Lighting Dependent
Performance degrades in extreme lighting , deep shadows, direct glare, overexposure, or very low ambient light. Collect training data that matches the lighting conditions of your deployment environment, including edge cases.
03
Feature Confusion
The model may confuse cracks with visually similar features: expansion joints, tile grout lines, painted seams, or wood grain patterns. Include similar-looking non-crack examples in training data and use negative examples to reduce false positive rates on specific surfaces.
04
Video Quality
Heavily compressed video, low resolution, motion blur, or narrow codec bitrates significantly reduce detection accuracy. For best results, use camera stabilization, adequate resolution (1080p minimum recommended), and high-quality codec settings during footage capture.
05
Training Data Required
The model must be fine-tuned on crack images representative of your target surfaces and conditions. A generic pretrained COCO model has no crack-specific knowledge. Minimum a few hundred labeled images is needed; 1,000+ labeled examples gives substantially better performance.
06
Screening Only
For cracks flagged as severe, or any crack on load-bearing structures, consult a licensed structural engineer or inspector. This tool is for initial triage and reporting, not final assessment. Do not use output reports as sole documentation for insurance, legal, or safety-critical decisions.
