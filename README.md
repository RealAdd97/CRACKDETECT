# Crack Detector

A complete pipeline for training a YOLOv8 object-detection model to locate cracks in images and videos. The system takes you from raw photos all the way to annotated videos with structured detection reports — three scripts, a clear data flow, and sensible defaults so you can get results quickly.

## What It Does

1. **Prepares your dataset** — copies images (and optional labels) into the folder structure YOLO expects, splits them into train/validation sets, and writes a `data.yaml` config.
2. **Trains a model** — fine-tunes a pretrained YOLOv8 checkpoint (YOLOv8n through YOLOv8x) on your crack images.
3. **Runs detection on video** — processes MP4 files or folders of videos, produces annotated output videos with bounding-box overlays, and generates JSON + CSV reports listing every detection with severity classification.

## Step-by-Step Usage

### Step 1 — Prepare Your Dataset

`prepare_dataset.py` copies your images (and labels, if you have them) into the standardized YOLO directory layout and generates `data.yaml`.

#### 1a. Organize Raw Images (No Labels Yet)

If you haven't annotated anything yet, just point the script at your images folder — it will create empty label files for you.

```bash
python prepare_dataset.py \
  --images_dir /path/to/your/images \
  --output_dir ./dataset \
  --val_split 0.2 \
  --class_names crack
```

Output:

```
dataset/
├── images/
│   ├── train/   ← 80% of your images
│   └── val/     ← 20% of your images
├── labels/
│   ├── train/   ← empty .txt files (to be annotated)
│   └── val/     ← empty .txt files (to be annotated)
└── data.yaml    ← auto-generated config
```

#### 1b. With Existing Labels

If you already have YOLO-format label files (`.txt`, one per image, same basename), include `--labels_dir`:

```bash
python prepare_dataset.py \
  --images_dir C:\crack_data\images \
  --labels_dir C:\crack_data\labels \
  --output_dir ./dataset \
  --val_split 0.2 \
  --class_names crack
```

#### 1c. Annotate Your Images

If you skipped labels, annotate them now using one of these tools:

- **[LabelImg](https://github.com/HumanSignal/labelImg)** — classic desktop annotator; set the save format to "YOLO" and draw bounding boxes around each crack. Output matches the expected `.txt` format exactly.
- **[CVAT](https://www.cvat.ai/)** — browser-based annotator with team collaboration. Export as "YOLO 1.1" format.
- **[Roboflow](https://roboflow.com)** — annotate and augment in the browser. Export directly to YOLO format with drag-and-drop upload.

After annotating, place the `.txt` files into the right split folders:

```
dataset/labels/train/  ← labels for training images
dataset/labels/val/    ← labels for validation images
```

#### YOLO Label Format

Each label file is a plain-text `.txt` with one line per bounding box:

```
<class_id> <x_center> <y_center> <width> <height>
```

All values are **normalized** (0.0–1.0) relative to the image dimensions. For a single-class dataset, `class_id` is always `0`. Example for an image that is 640×480 px:

```
0 0.500 0.375 0.250 0.200
```

This represents a bounding box at the center of the image that is 25% of the width and 20% of the height.

#### What If Some Images Have No Labels?

Use the `--missing_label_action` flag to control behavior:

| Flag | Behavior |
|---|---|
| `--missing_label_action empty` (default) | Writes an empty `.txt` file. The image is treated as a **negative example** (no cracks) — good for images you've inspected and confirmed are clean. |
| `--missing_label_action skip_copy` | No label file is written at all. |

**Recommendation:** use `empty` for images you've visually confirmed to have no cracks, and annotate images that *do* have cracks. A balanced mix of positive and negative examples trains a model that can also reject clean images at inference time.

#### `prepare_dataset.py` Arguments

| Argument | Required | Default | Description |
|---|---|---|---|
| `--images_dir` | Yes | — | Folder of raw images (`.jpg`, `.jpeg`, `.png`, `.bmp`, `.tif`, `.tiff`) |
| `--labels_dir` | No | `None` | Folder of YOLO `.txt` labels with matching filenames. Omit if not yet annotated. |
| `--output_dir` | No | `./dataset` | Where the organized dataset is written |
| `--val_split` | No | `0.2` | Fraction of images held back for validation (0.0–1.0) |
| `--class_names` | No | `crack` | Class name(s), space-separated. Most cracks use a single class. |
| `--seed` | No | `42` | Random seed for reproducible train/val splits |
| `--missing_label_action` | No | `empty` | `empty` = write blank .txt; `skip_copy` = no file |

### Step 2 — Train the Model

`train.py` fine-tunes a pretrained YOLOv8 model on the dataset you prepared. The best weights are saved automatically.

#### Basic Training Run

```bash
python train.py --data ./dataset/data.yaml --epochs 100 --model yolov8n.pt
```

#### Choosing a Base Model

The `--model` flag controls the YOLO variant:

| Model | Speed | Accuracy | Memory | Best For |
|---|---|---|---|---|
| `yolov8n.pt` | Fastest | Lowest | ~4 MB | Quick iterations, low compute |
| `yolov8s.pt` | Fast | Good | ~22 MB | Good balance (default) |
| `yolov8m.pt` | Moderate | Better | ~52 MB | Higher accuracy needed |
| `yolov8l.pt` | Slower | High | ~87 MB | Production quality |
| `yolov8x.pt` | Slowest | Highest | ~136 MB | Best accuracy, needs strong GPU |

**Rule of thumb:** start with `yolov8n.pt` for a first pass, then try `yolov8s.pt` or `yolov8m.pt` once the pipeline works end-to-end.

#### Full Training Command with Recommended Settings

```bash
python train.py \
  --data ./dataset/data.yaml \
  --model yolov8s.pt \
  --epochs 200 \
  --imgsz 896 \
  --batch 16 \
  --patience 50 \
  --device 0
```

#### `train.py` Arguments

| Argument | Default | Description |
|---|---|---|
| `--data` | (required) | Path to `data.yaml` from `prepare_dataset.py` |
| `--model` | `yolov8s.pt` | Pretrained checkpoint or `.yaml` config for training from scratch |
| `--epochs` | `200` | Maximum training epochs |
| `--imgsz` | `896` | Input image size (pixels). Larger = finer detail, more compute. |
| `--batch` | `16` | Batch size. Reduce if you hit CUDA OOM errors. |
| `--device` | `auto` | `0` = first GPU, `cpu` = force CPU, empty = auto-detect |
| `--patience` | `50` | Early stopping: stops if validation mAP doesn't improve for N epochs |
| `--lr0` | `0.01` | Initial learning rate |
| `--lrf` | `0.01` | Final learning rate factor (multiplied by `lr0`) |
| `--mosaic` | `1.0` | Mosaic augmentation strength (0.0–1.0). Mixes 4 images per training sample. |
| `--mixup` | `0.15` | MixUp augmentation probability. Helps with small datasets. |
| `--hsv_h` | `0.015` | HSV hue jitter |
| `--hsv_s` | `0.7` | HSV saturation jitter |
| `--hsv_v` | `0.4` | HSV value (brightness) jitter |
| `--freeze` | `None` | Freeze backbone layers for faster fine-tuning. `21` freezes backbone entirely. |
| `--warmup_epochs` | `3.0` | Linearly ramp up LR for first N epochs |
| `--lr_scheduler` | `cosine` | `linear`, `cosine`, or `cosine2` |
| `--close_mosaic` | `10` | Disable mosaic augmentation for final N epochs |
| `--project` | `runs/detect` | Root folder for training run outputs |
| `--name` | `crack_yolo` | Run subfolder (appended to `--project`) |
| `--resume` | `False` | Resume from the last interrupted training run |

#### Monitoring Training

Training progress is printed to the console in real time. Key metrics to watch:

- **`box_loss`** — bounding-box regression loss (lower = better)
- **`cls_loss`** — classification loss (lower = better for single-class, should be near 0)
- **`mAP50`** — mean Average Precision at IoU=0.5 (target >0.70 for usable results)
- **`mAP50-95`** — mAP averaged over IoU thresholds 0.5–0.95 (stricter, harder to maximize)

After training finishes, the script automatically runs validation on the best weights and prints:

```
mAP50: 0.XYZ  mAP50-95: 0.ABC
Next step — run detection on a video:
 python detect_video.py --model runs/detect/crack_yolo/weights/best.pt --source your_video.mp4
```

#### Reducing Memory Usage (Batch Size)

If you run out of GPU memory, reduce the batch size:

```bash
python train.py --data ./dataset/data.yaml --model yolov8m.pt --batch 8
```

Other options: lower `--imgsz` to 640, or switch to a smaller model like `yolov8n.pt`.

#### Resuming a Training Run

If training was interrupted (power outage, etc.):

```bash
python train.py --data ./dataset/data.yaml --model yolov8s.pt --resume
```

This picks up from the last saved checkpoint. You **must** pass the same `--name` and `--project` as the original run.

### Step 3 — Detect Cracks in Video

`detect_video.py` loads your trained model and runs inference on video files. It produces annotated videos and structured detection reports.

#### Single Video (CLI)

```bash
python detect_video.py \
  --model runs/detect/crack_yolo/weights/best.pt \
  --source inspection.mp4
```

Output in `./results/`:

- `inspection_annotated.mp4` — video with red bounding boxes drawn around each detection
- `inspection_report.json` — one JSON object per detection
- `inspection_report.csv` — same data in CSV format

#### Folder of Videos

```bash
python detect_video.py \
  --model best.pt \
  --source ./videos \
  --output ./results
```

Every `.mp4`, `.mov`, `.avi`, or `.mkv` file in `./videos` will be processed.

#### Report Only (Skip Video — Faster)

When you just need the data and don't need the annotated video:

```bash
python detect_video.py \
  --model best.pt \
  --source inspection.mp4 \
  --no_save_video
```

This skips the video writer entirely and only produces JSON + CSV reports. Much faster and uses less disk space.

#### Lowering False Positives

If you see too many false detections, raise the confidence threshold:

```bash
python detect_video.py \
  --model best.pt \
  --source inspection.mp4 \
  --conf 0.5
```

#### Force CPU or a Specific GPU

```bash
python detect_video.py \
  --model best.pt \
  --source inspection.mp4 \
  --device cpu          # force CPU (slow but no GPU needed)
```

```bash
python detect_video.py \
  --model best.pt \
  --source inspection.mp4 \
  --device 0            # first GPU
```

#### `detect_video.py` Arguments

| Argument | Required | Default | Description |
|---|---|---|---|
| `--model` | Yes | — | Path to trained `.pt` weights (e.g. `best.pt`) |
| `--source` | Yes | — | Single video file **or** folder of videos |
| `--output` | No | `./results` | Output directory for reports and annotated video |
| `--conf` | No | `0.25` | Confidence threshold (0.0–1.0). Raise to reduce false positives. |
| `--iou` | No | `0.45` | IoU threshold for non-maximum suppression. Lower = more aggressive deduplication. |
| `--device` | No | `auto` | `cpu`, `0` (first GPU), `1` (second GPU), or auto-detect |
| `--no_save_video` | No | `False` | Skip writing annotated video; generate reports only |

## Detection Reports

Each run produces two report files. Here is what they contain:

| Column | Type | Description |
|---|---|---|
| `video` | string | Source video filename |
| `frame` | int | Zero-based frame index |
| `timestamp_sec` | float | Position in seconds (frame / FPS) |
| `class_name` | string | Detected class (usually `"crack"`) |
| `confidence` | float | Model confidence, 0.0–1.0 |
| `x1`, `y1` | int | Top-left corner of bounding box (pixels) |
| `x2`, `y2` | int | Bottom-right corner of bounding box (pixels) |
| `bbox_width` | int | Bounding box width in pixels |
| `bbox_height` | int | Bounding box height in pixels |
| `severity` | string | `minor`, `moderate`, or `severe` (see below) |

The console also prints a per-video summary:

```
inspection.mp4: 42 crack detection(s) — minor=28, moderate=10, severe=4
```

### Severity Classification

Severity is a **heuristic score** used for triage — it is **not** a substitute for engineering assessment and does **not** measure real-world crack width (which requires a calibrated camera distance/scale).

The score combines two signals:

| Component | Weight | Description |
|---|---|---|
| **Size-based** | 60% | Normalized diagonal of the bounding box relative to the frame diagonal |
| **Confidence** | 40% | Raw model confidence score |

| Final Score | Severity |
|---|---|
| < 0.3 | `minor` — small or low-confidence detection |
| 0.3 – 0.6 | `moderate` — medium prominence |
| ≥ 0.6 | `severe` — large or high-confidence detection |

### Temporal Filtering

The detector uses a temporal consistency filter to reduce false positives from single-frame flickers. A detection is only reported if it appears in at least 2 out of 3 consecutive frames, with bounding boxes within 50 pixels of each other. These parameters are internal to `detect_video.py` and can be adjusted by editing `temporal_window`, `temporal_min_hits`, and `distance_threshold` in the `process_video` call.

## Tips for Better Results

### Dataset Quality

- **Aim for at least 200–500 annotated images** as a minimum. More variety = better generalization.
- **Include diverse crack types**: surface cracks, longitudinal cracks, transverse cracks, alligator cracking, potholes.
- **Include diverse conditions**: different lighting (overcast, direct sun, shadow), different surface textures (concrete, asphalt, tile), different angles.
- **Include negative examples**: images with no cracks. These teach the model what *not* to flag. Use `--missing_label_action empty`.
- **Balance the splits**: ensure both train and val sets contain roughly the same mix of crack types and conditions.

### Training

- **Start small**: use `yolov8n.pt` with 50–100 epochs to validate your data pipeline works, then scale up.
- **Use data augmentation**: the default `--mosaic 1.0` and `--mixup 0.15` settings are good starting points. They artificially expand your dataset by combining and modifying images during training.
- **Monitor validation loss**: if `box_loss` and `cls_loss` stop improving (check the console every 10 epochs), the model is converging. Early stopping (`--patience 50`) will halt training automatically.
- **Fine-tune the learning rate**: if the model is unstable (loss spikes), try `--lr0 0.005`. If it's converging too slowly, try `--lr0 0.02`.

### Inference

- **Adjust `--conf` per use case**: for safety-critical inspection, raise it to `0.5`–`0.7` to minimize false positives. For broad coverage, keep it at `0.25`–`0.35`.
- **Use `--no_save_video`** when processing many videos — it skips the expensive video encoding step.
- **Batch process**: point `--source` at a folder of videos for unattended processing.

## Troubleshooting

**Q: `CUDA out of memory` during training.**
Lower `--batch` (try 8 or 4), lower `--imgsz` (try 640), or switch to a smaller model (`yolov8n.pt`).

**Q: Training is very slow on my machine.**
Verify GPU acceleration is active: `python -c "import torch; print(torch.cuda.is_available())"`. If `False`, install the CUDA version of PyTorch.

**Q: Many false positives during detection.**
Raise `--conf` to 0.4 or 0.5. Also ensure your annotated training data includes enough negative examples (clean images).

**Q: The model detects nothing.**
Check that `--model` points to a real `.pt` file and that the model was trained on a dataset with labels. Verify `best.pt` exists under `runs/detect/<run_name>/weights/`.

**Q: I get "No video files found".**
Ensure the files in the `--source` folder end in `.mp4`, `.mov`, `.avi`, or `.mkv` (case-insensitive).

**Q: How do I use the GUI?**
Run `python detect_video_gui_integrated.py`. It requires Tkinter (included with standard Python on Windows and macOS; on Linux, install `python3-tk` via your package manager).

## Severity Disclaimer

The severity labels (`minor` / `moderate` / `severe`) are a **relative visual-prominence heuristic** based on bounding-box size and model confidence. They are intended for triage — prioritizing which clips a human inspector should review first — and are **not** a substitute for engineering assessment, calibrated measurement, or professional inspection. Real crack severity depends on width, depth, location, structural context, and material type, none of which this model measures directly.
